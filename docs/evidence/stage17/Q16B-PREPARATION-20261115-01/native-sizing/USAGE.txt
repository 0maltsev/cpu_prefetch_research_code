INPUT.json contains exactly capture, resources, monitoring, hardware_prestate.
The first three are the existing native service-input objects. hardware_prestate
is an explicit three-row [{"cpu": <uint32>, "value": <uint64>}, ...] declaration
from approved retained metadata. No value is inferred or read from hardware.
All native parser fields/monitoring paths must be supplied; paths are sized as
strings, never sampled. Resources may contain placeholder layout fields in
--describe; all seven region entries must exist. The capture memory ceiling
still applies. --verify-declared rejects stale native sizes.

Output layout contains exact core_bytes, monitor_bytes, total_mapping_bytes,
and seven region_bytes from describe_native_formal_service_layout. Output
workers contains every field of NativeFormalServiceCaptureLayout.workers,
including both phase raw requirements and offsets, optional ring/linked storage
requirements, object offsets and schedule offsets/counts. The ordinary native
parser rechecks the computed declarations before success is returned.
Total mapping includes the three native stack guard pages.

Link requirements established by successful build and link map:
  qualified release/lib/libcpu_prefetch_{runner_core,calibration,storage,
    lifecycle,timing,platform,workload,protocol,queue,foundation}.a
  GNU --start-group/--end-group handles archive dependencies;
  managed libcrypto.so, libzstd.so.1.5.7, -ldl, -pthread complete linkage.
Every project archive supplies object members, as recorded by service-layout.map.
Native capture execution code shares archive objects with pure layout code;
its presence in the link does not imply invocation. The caller only invokes
repository_info, JSON parsing/canonicalization, describe_native_formal_service_layout,
parse_native_formal_service_capture and native_formal_service_layout. Layout
construction performs checked arithmetic/storage sizing and static registry
lookup; it constructs no queue, starts no worker, reads no clock and accesses no
MSR/platform observations. The only input file read is INPUT.json; stdout/stderr
and local process resource limits are ordinary utility behavior.
