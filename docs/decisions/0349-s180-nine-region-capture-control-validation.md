Accepted engineering implementation of the already approved D310/D313/D334
native monitoring design. Immutable protocol files, completed calibration,
native34247ce, measurement durations/settings/sources and all operational limits
remain unchanged. No experiment, preparation or qualification is authorized by

## Actual gap and compatible route

The original retained-evidence decoder accepts seven declared regions and42
queries. The pilot's actual native publication has nine regions and54 queries:
the two additional mappings belong to the persistent shared context. Removing
those observations or projecting them into a seven-region success would lose
required evidence. A retained predecessor reproduction confirms the rejection;
the new route accepts the actual S180 identity and checks every region.

The original environmental API, discovery identity, report identity and default
seven-region contract remain unchanged. A separate `validate_s180_environment`
entry requires the actual pilot control identity, all nine independently bound
ranges and the same six complete retained source groups. It shares the existing
bounded delivery, smaps parsing, base-page/no-huge-page/full-lock checks. Its
report identity is `cpu-prefetch-s180-environment-validation/1`. The original
generic control checker defaults to42 queries; only its explicit pilot route
requires the two independently checked shared ranges, actual S180 identity and
all54 queries. Unknown/missing/extra/reordered evidence cannot select a subset.
