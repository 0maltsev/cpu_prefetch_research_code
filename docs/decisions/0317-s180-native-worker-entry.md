# D317: S180 native worker input and inherited-FD dispatch

Accepted engineering implementation, 2026-11-21, under the exact D310 S180
acceptance. Connect D315's typed Linux adapter to D316's archive handoff through
a separate versioned native worker entry. No scientific setting, observation,
count, window, recovery duration or immutable protocol is changed. This is the
native side of dispatch; the qualified parent must still authenticate actual
signed scoped admission before constructing its private context.

## Closed owned input

`parse_s180_session_input` accepts only the S180/1 plan and a separate S180/1
source context. The complete canonical blueprint must match the frozen approved
hash. Exactly180 capture records follow its execution permutation. Six retained
contexts, package/state/run identities, five/one-second windows, shared arena and
node namespaces, common schedule namespaces and accepted ring distances are
derived from those exact approved bytes. R2 evidence names the original accepted
descriptive freeze. These remain requested inputs, not fresh hardware readbacks.

All operational inputs are explicit: phase attempt/poll/drain bounds, raw buffer
capacities, initial state, stack owners/geometry, TLS/thread/environment/monitoring
limits, all nine regions, complete expected native layout, schedule endpoints/
counts and original artifact bindings, and per-capture/family finite resources.
There are no inline deadline vectors or caller-supplied shared views. Paired
treatments must agree on their original source bindings. The existing full-family
validator checks complete membership and descriptor/physical aliases, and the
existing cold source loader subsequently checks seals and original bytes before
any MSR entry. The parent separately proves accepted-generator provenance.

The parsed value owns its immutable JSON, prestate, source membership and reserved
descriptor list. Access rebinds all native spans after copies/moves; environmental
path views remain tied to the owned immutable document through native execution.
No mapping, schedule generation, hardware operation or worker thread starts while
parsing. A separate explicit `entry_metadata_bytes` reservation is removed from
the native family's output allowance before validation; entry publication cannot
borrow capture/finalization space.

## Native dispatch boundary

The separate internal CLI is `--execute-stage17-s180-session-v1`, with inherited
request/context/output-directory descriptors and the fixed end marker. It accepts
no path/stdin request, arbitrary command, output name, plugin, environment backend
selector, synthetic switch or Stage18 authority. Production constructs only the
Linux implementation. Software tests link a distinct implementation and require
both request/context to declare `synthetic_test_only=true`; production rejects
that declaration before publication or execution.

Request and context must be read-only, fully sealed, distinct bounded regular
descriptors. Limits are16MiB request and1MiB context. These are cold engineering
ceilings; the prospective parent admission must budget actual serialization,
parse/retained representations and all other resources. The worker enforces the
closed field sets, exact original request/plan hashes, matching identities and
prerequisite bindings, actual stand name from the frozen blueprint and explicit
`D310-S180-SCOPED-READY-v1` scope. Legacy generic readiness is not substituted.

Actual executable bytes/size must match request, release and context. The new
S180 identity uses a bounded streaming SHA256 reader with a256MiB executable
ceiling, including instrumented software-verification binaries without a second
whole-image allocation. Existing fixed-action profile/identity limits are
unchanged. `--stage17-s180-runtime-identity-v1` exposes the actual new role/profile,
source, size/hash and dirty flag without execution authority. Production requires
the exact clean compiled source revision.

The native entry binds original descriptive calibration/EXT007 hashes from the
frozen blueprint, and matching scoped EXT008/009/010, qualification, compatibility
and runtime-profile hashes from the parent's admitted request/context. It does
not independently verify their signatures or treat arbitrary hashes as proofs:
signed evidence validation and one-attempt journal consumption remain the
qualified parent's duties. The actual qualified S180 parent/admission route is
still required before any live invocation.

The context binds the actual boot, output device/inode and parent PID/channel
credentials, with no reserved descriptor aliases. Its original absolute window
must be exactly24h, already started and have room for the complete remaining
family envelope. Source preparation has its own unchanged bounded deadline.
Epoch authority must be current and cover the remainder of the original window;
it cannot expire while the native controller still has permission to run. No
new/reset window, retry or replacement follows from this entry.
Whole-second epoch reads require a conservative extra fractional-second margin:
equality after rounding the remaining monotonic interval does not prove coverage.
This tightens admission without changing the24h monotonic operational limit.

Before execution, a durable create-exclusive `s180-session-entry.json` records
actual request/plan/authorization/prerequisite/source/runtime/boot/window lineage.
Its bytes must fit their separate reservation. Existing markers reject replay.
The native adapter then owns the frozen180-attempt state machine, first-failure
stop, retained private/shared cleanup and restoration. Completion returns exit0
only with the explicit completed terminal state, verified restoration and no
quarantine. Failures retain the entry/attempt/final evidence already published.

## Durable archive acknowledgement

The entry's fixed S180 sink uses D316's parent credential/hash/ordinal channel.
After a normal ACK it also opens the original custody receipt relative to the
held output root, requires bounded actual bytes/size/hash and checks the original
archive deadline. Missing or changed custody bytes latch failure and cannot
return normal continuation. Negative ACKs retain D316's stop behavior. Final
failure publication remains possible. This extra native check does not replace
the parent's mandatory actual broker/ledger/inverse/cleanup verification.
