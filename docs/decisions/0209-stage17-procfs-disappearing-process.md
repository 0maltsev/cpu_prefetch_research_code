# ADR-0209: Treat ESRCH as a vanished procfs scan candidate

- Status: `ACCEPTED` — necessary engineering correction during approved D207 qualification
- Date: 2026-11-03
- Scope: process identity scanning and regression coverage; no experiment-design change

The full development suite passed 641 of 642 checks. The process-supervisor
check failed while scanning `/proc`: a process disappeared during a status
read, producing `ESRCH` (`ProcessLookupError`) instead of `ENOENT`
(`FileNotFoundError`). The test used the historical v2 implementation; the
current v3 implementation has the same narrow exception classification.

The current v3 identity scanner will classify either exception as a vanished
scan candidate. It continues to reject permission/I/O errors, malformed or
ambiguous identities, a missing requested leader, and unresolved owned-child
identity. It does not treat a failed scan as proof of quiescence, relax held-
leader or namespace checks, add a retry, or alter signal/reap ordering.
Historical v2 bytes remain unchanged. Policy57 pins the corrected current v3
and the regression checker; older qualified archives retain their old bytes.

The preflight renderers must also recompute the existing operational-runtime
bindings when explicitly generating a policy against a source tree. Previously
they copied the old supervisor hash from the predecessor policy, so the
unchanged semantic verifier correctly rejected the newly rendered policy.
Refresh those hashes using the same declared paths in renderers 56 and 57;
do not change any checked-in predecessor policy, implementation identity or
verification rule. Both current and historical temporary-projection checks
must validate their generated bytes against the supplied source tree.

Regression coverage uses the current v3 implementation, exercises ESRCH at
each wrapped procfs read, and checks missing-target/owned-child rejection and
propagation of other errors. The original real process-group, signal, waitid,
namespace and reuse checks remain. Source-order assertions inspect the actual
re-exported cleanup implementation rather than assuming its file location.

Retain the initial full-suite failure. Require the deterministic regression
and affected process/admission checks to pass before qualification. This
Python change requires no new native measurement code or scientific approval;
it grants no stand invocation beyond D207's already accepted finite scope.
