# ADR-0231: Explicit v6 formal admission, execution and custody

- Status: `ACCEPTED` — scoped engineering integration; verification in progress
- Date: 2026-11-03
- Scope: EXT007 persistent formal families, no new scientific method or run authority

The historical Python controller/executor/registry routes still bind the v4
collectors. Add explicit controller v25, executor v10, registry v11, v6 action
documents and fixed-action profile v8 for the D227 entry point. Preserve all
unrelated action permissions and historical v4/v5 routes. The new release must
be fully qualified under a successor bundle profile before this path can admit
an action. Importing these modules or passing local tests grants no authority.

Require a complete prospective family and exact prior evidence bindings before
execution. Q16a recomputes the unchanged D207 count-only selection from the
complete independent validation summary and uses its selected duration and
100,000-observation minimum. Q16b/Q16c require preceding independent calibration
records from the same qualified release and stand. Native completion and raw
custody cannot substitute for those records. Bind namespace registration to
the complete prospective identities and exact plan bytes. Q16c retains and
checks the exact bound source schedule vectors; an empty warmup vector is
representable, while measurement still requires offered events under D036.
These records do not silently waive namespace governance or scientific freezes.
The source check uses D232's original binary, envelope and derivation bytes,
the accepted generator, exact Q16b-derived rate and the parent in the bound
prospective namespace registration. It does not prove D036's separate
common-marginal family assumption. The registration lists both all capture
phase identities and all schedule namespace/seed/parent/phase identities.

Recompute the preceding record's complete D230 coverage and exact arithmetic;
a `VALIDATED` header alone is insufficient. Prior Q16a must retain the accepted
discovery duration and minimum. All subsequent ring contexts retain its capacity
and cache-line geometry. R2 uses the corresponding context's calculated distance
in both hardware states, with `calibration_evidence_id` equal to
`q16a-sha256-<exact original calibration-record SHA256>`. This names the bound
record without treating its digest as independent provenance authentication.

Preserve the existing journal/trust/signature/state checks, sealed request and
context snapshots, current authority checks immediately before the worker,
one-attempt markers across predecessor versions, process-group supervision,
quiescence proofs, live restoration, failure retention and quarantine. Use the
prospective family and maximum capture watchdogs rather than historical fixed
180/3600-second limits. Check fresh MemAvailable and free space on the pinned
output filesystem before the marker and at the immediate worker boundary.
Retain the final resource observation in the completion receipt. Availability
is an observation, not an OS reservation or proof that unspecified heap reserves
are sufficient; exact native layout and prospective resource planning remain
required.

The worker supervisor's deadline is the earlier of the prospective family
deadline and the signed authority's monotonic expiry, with the existing cleanup
reserve preserved. Authority checked only before process creation is insufficient
for a long family. On failure, hardware restoration may begin only after the
worker leader is reaped and its process group is proven gone. Missing or false
cleanup proof requires retained failure evidence and quarantine; it cannot
trigger a concurrent MSR restoration attempt.

The complete release uses bundle profile v26 (hermetic v22), release verifier
v12, operational semantics v16, policy v58, journal v52 and CLI v18. Preflight
policy/executor v32 bind that same journal while preserving the read-only action
contract. Q15 session controller v20 preserves the existing qualification
procedure against the successor journal. Historical standalone entry points
retain their versions. The release includes the seven prior generated-code
gates and the additional actual formal-worker gate under both disassemblers.

Custody admission requires every original warmup/measurement artifact, exact
role/schema/name/count, streaming size/SHA verification, per-capture and family
output bounds, the exact canonical plan hash, complete final-cleanup membership
and D213's H0 no-write/H1 reverse-restore action vectors. The report remains
`NOT_ASSESSED` scientifically, with no execution or Stage 18 authority. Original
per-capture control evidence, all raw reconciliation, family estimator gates,
sealing and EXT007 admission remain separate required checks.
Hash and parse the retention report from the same bounded descriptor snapshot;
a hash followed by reopening for JSON parsing is not a byte binding. Check
descriptor/path identity and reject duplicate keys or nonfinite JSON values.
Post-run retention preparation may authenticate an expired v6 authority for
custody only; execution preparation still rejects it. Both paths preserve
signature, prospective duration, release and predecessor checks.

Test all three artifact naming families and a real-file complete Q16a custody
fixture, including missing/duplicate/path/hash/role and restoration mutants.
Test complete and corrupted prerequisite bindings, source/qualified-pair
identity, prior-selection recomputation, live resource failure and explicit
version separation. End-to-end authenticated execution and successor bundle
qualification remain pending until separately verified; unit and custody
tests must not be reported as full operational readiness.
