## One bounded state machine

The typed controller accepts one parent-authenticated session identity/plan hash
and one already established absolute24h window. It never creates or resets that
window. Current monotonic time must fit the entire remaining family envelope;
source preparation has a separately bounded setup deadline. Time is rechecked
before attempts and hardware/capture actions, including after marker publication;
a regression or expiration blocks progress.

The same fixed controller is used with the internal Linux adapter and separately
linked software-test operations; there is no runtime plugin/backend selector.
All preparation and prospective native layouts precede MSR entry. Each durable
capture marker is emitted once. Warmup/measurement run once, then the original
evidence is checkpointed and offered for archive custody, even if capture fails.
The first capture, custody, source/resource, marker, hardware or clock failure
ends collection. There is no retry, top-up, replacement or additional repetition.
FULL/low-effective-count outcomes are not new retry conditions.

Hardware restoration separates the two frozen whole plots. An explicit
prospective recovery interval, including zero when the eventual frozen parent
plan specifies none, is an input; no scientific duration is chosen here. Transition
restoration overhead has a separate operational allowance. The actual recovery
value/meaning must be bound by scoped admission before execution. Final hardware
restoration, release of all six contexts and final publication share one deadline;
these actions cannot each obtain a new finalization allowance. Failure preserves
its original stop reason plus actual restoration/cleanup/publication outcomes.
All prepared contexts are released after join, including partially prepared
families, and no later failure can become successful completion.

## Linux wiring and evidence

The Linux adapter uses existing owner mappings, native pilot capture, registered
hardware-prefetch writer/verifier, real CPUID and cold kernel deadline guards.
It prepares six contexts once. The18 pairs of source vectors are decoded once
and retained with shared immutable ownership; all180 capture layouts are checked
against their complete declarations before MSR entry. Each capture copies only
its selected original arrays into its private read-only owner mapping.

The adapter publishes the D314 eight-artifact capture set, a durable attempt and
a new S180 checkpoint containing the returned native result after private cleanup.
A distinct `S180ArchiveSink` must have a qualified checkpoint capability and the
same program-scope hash; a historical generic sink cannot be used accidentally.
The acknowledged S180 custody schema/role is checked. The parent broker remains
responsible for D310/D233 lossless reconstruction/publication/release policy.
Publication/acknowledgement bytes count against the frozen output bounds.

Final family evidence records complete actual post-release owner-map evidence
for all six contexts; unavailable contexts stay null. Whole-plot records distinguish
requested state, cumulative helper evidence and fresh independent complete-value
restoration reads. Per-capture private cleanup never stands in for final shared
cleanup. Native completion remains an operational scoped result, with no Stage18,
scientific validity, covariance, final feasibility or legacy readiness promotion.

Native execution requires exact clean repository revision and scope-bound S180
custody capability. These guards are not authentication or admission. The parent
must authenticate the entire serialized prospective input/authority, bind actual
EXT008/009/010, qualification/compatibility and source provenance, and supervise
hard termination/reaping/restoration. Existing fixed-action and durable-pilot
CLI contracts remain unchanged and reject the unadmitted new route.
