# Implementation Decision Register

Protocol version: **`2.0.0-pre.1`**

Register date: **2026-08-17**

Stage 2 state: **`COMPLETE; Q1_Q2_Q3_Q4_ACCEPTED`**

`ACCEPTED` means an ADR freezes the choice. `PROPOSED` is a recommendation awaiting explicit owner acceptance. `UNRESOLVED` is not a default. `PROTOCOL_FIXED` restates source-of-truth behavior and is never an engineering choice. A selected implementation that changes scientific meaning requires a versioned protocol amendment, not merely an ADR.

## Protocol-fixed boundary

The immutable snapshot fixes Stage A treatments and counts, record semantics, open-loop one-attempt arrivals, timestamp boundaries, queue package behavior, producer/consumer independence, reconciliation identity, equations, quantiles, lifecycle states, partial-failure retention, zero-loss and low-`N_eff` rules, complete-block replacement, H1/H2/H3 analysis chronology, and requested-versus-verified hardware state. Stage B and Stage C remain outside scope. No item below may reinterpret those rules.

## Evidence reviewed for Stage 2

Repository and environment evidence was supplemented by primary/official technical sources. These sources establish candidate feasibility and provenance only; they do not accept a choice or qualify the target stand.

- **Queue paper and artifact search:** M. Torquati, *Single-Producer/Single-Consumer Queues on Shared Cache Multi-Core Systems*, [arXiv 1012.1824](https://arxiv.org/abs/1012.1824) and [University of Pisa TR-10-20](https://calvados.di.unipi.it/storage/paper_files/TR-10-20.pdf). The [author-maintained FastFlow repository](https://github.com/fastflow/fastflow) is an official current project artifact and states dual LGPL-3.0/MIT licensing for current releases. It does not, without an immutable historical mapping, establish the exact source revision or applicable license for the queue algorithms evaluated in the 2010 report. Status is therefore `CURRENT_OFFICIAL_PROJECT_FOUND; EXACT_PAPER_ARTIFACT_UNRESOLVED`. No queue source was downloaded or reused.
- **C++/toolchain feasibility:** the [C++ atomic-order specification](https://eel.is/c++draft/atomics.order) and [generic atomic lock-free rules](https://eel.is/c++draft/atomics.types.generic) make the proposed release/acquire mapping expressible while leaving lock freedom implementation-defined. [GCC 16 changes](https://gcc.gnu.org/gcc-16/changes.html), [Clang 22 release notes](https://releases.llvm.org/22.1.0/tools/clang/docs/ReleaseNotes.html), and [libc++ C++20 status](https://libcxx.llvm.org/Status/Cxx20.html) support a capability probe, not a blanket guarantee.
- **Build/test baseline:** official [CMake Ninja generator](https://cmake.org/cmake/help/latest/generator/Ninja.html), [GoogleTest CMake quickstart](https://google.github.io/googletest/quickstart-cmake.html), [RapidCheck](https://github.com/emil-e/rapidcheck), [AddressSanitizer](https://clang.llvm.org/docs/AddressSanitizer.html), and [ThreadSanitizer](https://clang.llvm.org/docs/ThreadSanitizer.html) documentation. ADR-0022 and `config/dependencies.json` now record the constrained versions, sources, hashes, licenses, and completed offline compatibility probes.
- **Deterministic/integrity candidates:** [Random123](https://github.com/DEShawResearch/random123) publishes Philox counter-based generators under BSD-3-Clause; [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785.html) supplies JSON canonicalization rules but its I-JSON number model cannot be allowed to coerce the protocol's exact large integers; [OpenSSL EVP SHA-2](https://docs.openssl.org/3.5/man7/EVP_MD-SHA2/) supplies the proposed vetted SHA-256 dependency.
- **Linux platform candidates:** official/man-pages documentation for [`sched_setaffinity`](https://man7.org/linux/man-pages/man2/sched_setaffinity.2.html), [NUMA memory policy](https://www.kernel.org/doc/html/latest/mm/numa.html), [page migration/residency](https://www.kernel.org/doc/html/latest/mm/page_migration.html), [transparent huge pages](https://www.kernel.org/doc/html/latest/admin-guide/mm/transhuge.html), [CPU frequency control](https://www.kernel.org/doc/html/latest/admin-guide/pm/cpufreq.html), [kernel timekeeping](https://www.kernel.org/doc/html/latest/timers/timekeeping.html), and [`CLOCK_MONOTONIC_RAW`](https://man7.org/linux/man-pages/man3/clock_gettime.3.html). CPU-specific HW-PF fields still require the exact target vendor manual, authorization, readback, probes, and rollback evidence.

The observed development environment (Linux 7.0.11 x86-64, GCC 16.1.1, Clang 22.1.6, CMake 4.3.3, Ninja 1.13.2, AMD Ryzen 5 5500U, one NUMA node) is capability evidence only. It is not an eligible near/far stand and supplies no empirical result.

## Later protocol-defined decisions with open values

Before confirmatory execution, the protocol still requires treatment-blind values/evidence for `delta_star`; cache-derived capacities/residency maps; rates and `mu_ref`; whole-matrix zero-loss inputs; ring `d2`; horizons/warm-up/moving-block/recovery values; repetitions/bootstrap budget; master/derived seeds and immutable roles; replacement budget/authority; H3 signatures/access; environmental limits/counters; and stand-hours/final block plan. These are Stage 6-8 outputs under the fixed rules, not Stage 2 defaults.

Submission identity, venue, accessibility, archival license, and final metadata remain submission-only decisions.
