# D291: use the selected private archive namespace for retained custody

Accepted engineering repair within the existing CPU research software scope.
This decision grants no retry, new execution window or experimental authority.

D288 stopped at the first checkpoint metadata read, before independent raw
validation, qualification or collection. Its public capture registry constructed
`PhysicalBinding` through the public custody module. The authenticated archive
profile loaded custody and archive under private module aliases. Python dataclass
equality rejected the foreign binding type despite identical size and SHA256.
The original failed service and its recovery receipts remain unchanged.

The retained-prefix caller now makes a private capture-registry namespace from
the unchanged registry function bodies. All locally defined helpers share one
globals dictionary bound to the selected archive and custody modules. This covers
checkpoint and receipt reads, ledger records, source bindings, role profiles and
physical archive verification. It changes neither the historical archive runtime
nor its strict binding equality, hash, inode, ledger or checkpoint checks. Public
modules are not patched. Decoder and custody limit objects already use the
selected namespace and retain their original bounds.

All86 complete-capture checks use this registry. The exact failed86 diagnostic
uses the same registry while retaining its existing incident-bound requirement
for native_complete=false and stop10. It remains excluded from scientific credit.
Suffix admission uses the existing public-store/public-registry scope; a real
eight-artifact fixture checks that separate boundary without changing its code.

Verification includes actual authenticated private source imports, a real
eight-artifact archive/ledger fixture, complete and failed checkpoints, wrong
size/hash, archive corruption, ledger corruption and read-only inventory parity.
A metadata-only UID1000 stand probe reproduced the old rejection and passed the
repaired reader for original checkpoint/receipt pairs at ordinals0 and86. It
opened no raw archive stream or ProgramStore transaction and ran no validation
or measurement. The runtime profile and original evidence were unchanged.

Policy63's current runtime closure is regenerated for the changed cold helper.
The consumed release6993313 and every historical bundle/policy snapshot remain
unchanged. Any successor package must have its actual clean revision and exact
source/worker/packet identities verified before execution. No native measurement
code or scientific dependency is changed. Python-only namespace changes introduce
no modified C/C++ sanitizer target; existing codec/native sanitizer evidence is
not claimed as fresh verification of this repair.

The private-runtime integration gap in the earlier tests is recorded explicitly:
the original retained-prefix fixture used public registry and store types. The
new tests reproduce the differing private dataclass identities rather than
weakening equality or using a truth-only custody proof.
