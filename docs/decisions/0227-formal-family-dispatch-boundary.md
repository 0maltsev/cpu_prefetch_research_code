# ADR-0227: Explicit persistent formal-family dispatch

- Status: `ACCEPTED` — scoped engineering integration; verification pending
- Date: 2026-11-03
- Scope: EXT007 Q16a/Q16b/Q16c software only
- Scientific authority: D035/D036/D037, accepted D211/D212; no new run authority

The historical v4 formal dispatcher calls the older collectors. The new typed
persistent collectors must have an explicit successor entry point; a new JSON
shape must not silently select a different collector through an old request.

Add the fd-only v6 entry point for Q16a/Q16b/Q16c, with v6 request, context and
result identities. It invokes a separate virtual formal-family operation.
Historical v4 actions and v5 discovery remain on their existing routes. The
production executable has no synthetic-backend switch. The separately linked
test executable may publish an unmistakable software-only boundary fixture.

Before touching hardware, validate complete prospective coverage and every
native capture layout. A family has explicit phase identities, namespaces,
durations, capacities, memory/output/deadline declarations and clean source
identity. Q16a requires at least 59 prospective repetitions of each of its 12
contexts; Q16b requires at least 59 per 60 cells. A Q16c family represents one
prospectively declared candidate from the accepted five-point ladder and all
180 cells. Its count declaration does not establish feasibility or permit an
unplanned extension. The future signed plan must supply the actual values and
all prerequisite evidence; these software constraints choose none of them.

Represent execution order explicitly as contiguous H0 and H1 whole plots, then
package, placement, working-set class, load (Q16c), repetition. Cell identities
remain package-major. The actual prospective order requires plan admission;
this implementation record is not an authorization to execute that order.
Warmup and measurement identities are distinct and unique throughout the
family; the arena uses the already accepted measurement-seed convention.
Repeated cells preserve their declared bounds and paired hardware states
preserve the same package/context geometry.

Use checked integer arithmetic for complete raw-stream extents, publication
copies, declared mapping/other memory, watchdogs and retained output. Include
linked node order (capacity plus one nodes) and both Q16c source schedules.
The family watchdog covers every capture watchdog plus declared setup/cleanup;
the v6 context must bind the exact ceiling-rounded per-capture maximum and
family deadline. Resource declarations are consistency checks, not evidence of
available memory/disk or sufficient unspecified heap reserves. Admission still
requires native sizing, measured resources and complete release qualification.

Preparse the entire family before hardware entry. For each capture, retain
original raw/control files, run with the declared finite deadline, and preserve
the returned native result after cleanup separately from its publication-time
snapshot. Stop on the first mandatory failure, restore the active whole plot
and retain the failed prefix and restoration evidence. No failed capture is
retried or replaced here. FULL and low counts remain independent scientific
gates; native completion is not scientific validity.

The successor retention report identifies the exact canonical plan, raw
bindings, per-capture final native results and whole-plot action readbacks. It
explicitly says scientific validity is unassessed. Independent reconciliation,
calibration estimators, evidence sealing and EXT007 admission remain required.

Verify complete families, missing/reordered captures, repeated identities,
source/method drift, outcome-adaptive bounds, overflow and incomplete budgets.
Exercise the real fd boundary with the test-linked worker: version separation,
current authority, exact plan-derived deadlines and runtime/context identity.
Preserve existing discovery and formal publication regression checks and run
relevant sanitizers before a qualified release. No experiment may start from
this unqualified working tree.
