# D333 proposal: extend the existing locked-page compaction control to S180

Status: **PROPOSED — scientific platform approval required before activation**.
Amendment ID: AMEND-2.0.0-pre.3-S180-LOCKED-COMPACTION-v1.
This proposal creates no approval, qualification, source bank or run window.

## Exact requested extension

Apply the previously reviewed D286 locked-page compaction method to the single
owner-approved D310 S180 pilot. While its native qualification/pilot family owns
the platform, request `/proc/sys/vm/compact_unevictable_allowed=0` under one
exclusive root-held lease. Record actual prestate independently; never assume
the old restored value or overwrite a foreign lease. This is a new prospective
platform regime, not an editing or relabeling of any historical observation.

Bind the original accepted guard source and its code/profile ancestry, current
boot, real prestate, requested zero, actual readbacks, owner identity and original
absolute deadline in the pilot's qualification/platform evidence. Verify at the
family/capture release and checkpoint boundaries outside the measured worker
loop; retain independent phase control readbacks in the original capture data.
Preserve every existing page-location, NUMA, observation deadline and failure
gate. Do not accept or retry a negative observation because the guard was used.

On any error, stop and reap the owned native/codec workers before restoration.
Restore the exact observed original sysctl value, independently read it back and
durably publish restoration before clearing the lease. Bind a systemd stop-post
recovery action for supervisor death, including actual owned-worker quiescence
and lease/boot/prestate checks. Unknown/live ownership or failed recovery leaves
an explicit occupied/quarantined state; never replace evidence or auto-retry.
No unsupervised guard invocation is authorized.

## Unchanged design and operational conditions

Keep all180 settings once,5s warmup,1s measurement, original rates, source
generator/seeds/namespaces, common pairing, ordering, geometry, independent raw
observations and all scientific estimators/limits. Keep the existing stop on
first new qualification, validity, custody, resource, time or restoration failure.
Keep stand-only lossless custody and the original shared6TB/512GiB/256GiB/16GiB
budgets. Recompute the exact small control/metadata overhead before admission;
if the unchanged complete resource/time envelope cannot fit, do not launch.

Use the same single24h window, anchored by the first actual schedule preparation
or qualification action. This extension grants no second window, reset, retry,
recalibration, qualification reuse or independent new experiment. Actual
qualification and exact EXT008/009/010 admission remain required. Present the
complete ETA before any operational start. Correctly reconciled FULL and low
effective count remain retained outcomes; Stage18 remains outside this approval.

## Why this decision is separate

D286 explicitly says its scientific change is "for future Q16c work only".
D310 approves a new pilot under a verified platform regime but does not explicitly
extend that narrowly scoped sysctl change. AGENTS.md requires a versioned amendment
for a missing scientific decision; it cannot be supplied silently by code or by
changing ordinary file permissions. The existing method addresses the previously
recorded locked-page movement failure without weakening observation gates.

Owner choices are: approve this exact extension for the single S180 family, or
retain the existing platform setting and its unchanged observation/failure gates.
The second choice does not authorize the guard or relaxation of a failed gate.
All completed calibration and failed evidence remain preserved under either choice.
