The executor failure receipt says restoration_verified=true and records matching
zero readbacks on CPUs 8, 1, and 0. Fresh independent reads also returned zero.
The supervisor checks receipt.get('quarantined') is False, but the failure/6
receipt has quarantine_operation.performed=false instead of a quarantined field.
The missing key returns None; thus the supervisor reports false. This exact
expression was evaluated against the retained receipt and the defect confirmed.

The separate PermissionError(13) during partition cleanup remains real. The

writing before removing the cgroup. That file is now absent, consistent with
loss of the controller. Attempting creation in the cgroup filesystem is a likely
explanation for this permission error, but no traceback/syscall was retained
to prove the exact failing line. No reproduction was attempted on the stand.

Fresh readback: root effective CPUs 0-31, isolated set empty, root controllers
